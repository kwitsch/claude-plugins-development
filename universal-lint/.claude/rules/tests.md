# Tests

- `tests/*.test.mts`, one file per language/tool (ported from the bats suite of kwitsch/claude-plugins, one `.bats` file per language/tool): `core`, `checkstyle`, `go`, `markdown`, `npx-fallback`, `oxlint`, `php`, `rust`, `stylelint`, `truncation`, `tsc`, `yaml`, `skill`, `file-detection` (SessionStart/CwdChanged watch list and FileChanged linting in a real git repo, with the local `git`/`gitInit` helpers); plus `registry.test.mts` (unit tests of the exported helpers of the built `plugin/hooks/lint-file.mjs`, the former `registry.test.mjs`), `spawn-group.test.mts` (the `spawnGroup` process-group spawn, its timeout and kill escalation) and `manifest.test.mts` (wiring: no `userConfig`, hooks.json, exec bit, README). The bats scaffold/marketplace/root-README checks are replaced by the repo-wide guards (layout allowlist, manifest generation, CI freshness).
- `tests/support/lint-hook.mts` is the shared harness, not a test file (vitest only runs `*.test.mts`; the subfolder follows `development/vitest/claude-engine/tests/mods/`). It is hermetic: `PATH` holds only `bash`, `node` and `git` (symlinked) plus the linter stubs a test adds (`makeEnv().recStub(name, exit)` records `<name> <argv>`, prints `$OUT`, exits; remove the `git` symlink before stubbing `git`, or the stub overwrites the real binary), `HOME` and `CLAUDE_PLUGIN_DATA` are per-test temp dirs, `GIT_CONFIG_NOSYSTEM=1`, and the built `plugin/hooks/lint-file.mjs` is spawned per run. `run(file)` pipes a PostToolUse payload, `runEvent(payload)` any payload (FileChanged, SessionStart, CwdChanged), both through `spawnSync` `input` (stdin is a pipe fed up front); `HookRun` carries `status`, `stderr`, `stdout` and `ctx`. `RunOptions.toolName`/`toolResponse` shape Edit payloads (`structuredPatch` hunks drive the edit-range gate).
- Tests run against the built `plugin/`: run `pnpm --filter universal-lint build` after changing `src/` before `pnpm --filter universal-lint test`. A helper used by one file stays local to that file.
- Late or large stdin (F05): `core.test.mts` drives the hook with its local `runLate` (async `spawn`, stdin pipe, a 512 KB payload written 100 ms after the spawn), the case 0.15.3's synchronous fd-0 read dropped with EAGAIN. Since 0.15.4 the hook reads stdin asynchronously, so concurrent hook runs (e.g. a burst harness) may feed stdin from a file or any pipe; drive them with async `spawn` (`spawnSync` runs one hook at a time).

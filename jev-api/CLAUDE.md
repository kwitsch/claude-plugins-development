# jev-api

Mods-only plugin: a function-hooks module that registers the System One question types `noul`, `choice`, `score` as tools (`mcp__jev-api__<type>`), plus `batch` (`state` and a `questions` array of `{ type, instructions, criteria }`, one request, answers as a JSON array in question order, all or nothing), and answers them. jevfort asks Jev only through `batch`: renaming it or changing its input or answer shape breaks jevfort.

- `src/hooks/register.mts` holds everything: no imports, HTTP through `$.http.fetch`. Two matcher-less hooks: `session.start` registers the four tools (a failed one is logged via `$.ui.log`) and records the name the engine returned for each (only in the `mcp__<plugin>__<type>` form) next to the default `mcp__jev-api__<type>` names, `tool.call` answers those names and passes every other tool to `next(e)`. A registered tool that no hook answers fails, so never call `next(e)` for `noul`/`choice`/`score`/`batch`, and the hook catches its own throws (a refused `$.env.get`) to answer them too.
- Registration (0.3.2): a tool whose `$.tool.register` failed stays in `missing` and the next hook (session.start or an owned call) registers only those again; registration is a state per tool (`RegState`, `ensureTools`): a tool refused again is retried once at once, then after 5 s, 10 s, ... (max 5 min) and logged once; the wait for a registration is bounded (1 s in an owned call, 5 s in session.start) and paid once per hanging tool (it is then `stuck`: other tools and later calls do not wait for it), so a registration that never answers does not hold a call. The Haiku call carries the dispatch's abort signal. An invalid call is answered before any env read, an already abandoned call sends nothing, and the abort listeners are removed when a call settles. A timed-out or abandoned request is not cancelled (the engine's fetch has no `signal`): callers keep `timeout` at or below their own budget (jevfort: equal to its 4 s budget, 9 s for a compaction ranking). The Haiku output budget (`haikuTokens`) grows with the options and levels the answers list (cap 16384).
- Errors are `{ deny: "<tool>: <reason>" }` (`batch` input errors name the question: `questions[<i>]: ...`): core drops a hook's own `isError` (live on 2.1.322 the model got the error as a normal result), while a `deny` reaches it as an error result.
- `register(on)` has no `$`, so the tools cannot register at module load; `ensureTools($, st, ms)` runs in `session.start` and, best effort, at the start of `tool.call` (a call before session.start still registers). Tools stay deferred (MCP-style, ToolSearch).
- Haiku fallback (0.3.0): after input validation, if none of `TYPESAFE_API_KEY`, `TYPESAFE_BASE_URL`, `JEV_URL` is non-blank, `askHaiku` asks `$.model.complete` (`claude-haiku-5-5`) for `{ answers: { <id>: <answer> } }` JSON and `checkAnswer` rebuilds each answer in the System One shape (noul 0..1; choice must be an option with all option probabilities; score 0..levels-1 with all level probabilities; confidence 0..1), else `<tool>: fallback: ...` (never a made-up answer). A configured Jev that fails stays an error. Not a `claude -p` spawn (decided: effortless and jevfort use the engine call). jevfort raises its budget to 15 s in that case.
- Haiku calibration (0.3.1, measured 2026-11-13 with `claude -p --model claude-haiku-5-5` on the 60 labelled DE/EN effort prompts of the jevfort evaluation, exact plugin questions and state; harness and results were scratch files, not in the repo): raw Haiku overestimated (A2 hit rate 91 of 119 against Jev's 103; mean score for high/xhigh/max prompts 2.71/3.13/3.71 against Jev's 2.4/2.86/3.22) and said 0.8 to 0.93 where Jev says >= 0.95 for mechanical prompts (4 of 24 low prompts >= 0.95, Jev 22). Fixes: (1) `HAIKU_SYSTEM` ends with a calibration paragraph (use the full noul range, spread probabilities, lowest level that fully handles the case, no whole-number scores), (2) `checkAnswer` ignores Haiku's own `score` and derives it as the mean level index of the normalized probabilities (like Jev's expected value; Haiku's `score` was rounded toward whole levels), probabilities normalized to sum 1, (3) `noul` is stretched in logit space by `NOUL_STRETCH` 2.5 (`stretch`). Result over two independent 120-request runs with the shipped prompt and transforms: A2 100 to 108 of 120 (Jev 103), A5 44 to 50 of 60 (Jev 53, criterion 50; raw Haiku 47, so no reliable gain there), mechanical low 17 to 18 of 24 and medium 0 (Jev 22 and 0); run-to-run spread is about 8 hits, so treat the numbers as +-4. Only the effort rubric and the mechanical question were measured; the stretch also applies to every other `noul` (jevfort's take/done/single-action questions), which Jev answers confidently too, but that is unmeasured. Not calibrated: `choice` (kept as Haiku gives it) and the 4-level difficulty rubric.
- Endpoint (only with a variable set): `JEV_URL` > `${TYPESAFE_BASE_URL}/v1/systemone` > `https://api.typesafe.ai/v1/systemone`; an invalid set value is an error, never a fallback. Model `TYPESAFE_DEFAULT_MODEL` or `jev-latest`; timeout via `$.clock.after`, cancelled when the request settles: the call's optional `timeout` input in seconds, else the `userConfig` option `timeout` (`register(on, options)`), else 20 s; a value counts only as a finite number > 0, anything else falls through silently, and above 30 it counts as 30 (`MAX_TIMEOUT_S`: the engine caps one `$.http.fetch` at 30 s itself, and the engine's `$.clock.after` is Bun's setTimeout, which fires a delay past 2^31-1 ms at once); an aborted `next.signal` answers at once. The engine's fetch errors quote the URL, so `ask()` puts the variable's name in its place. The bearer key is sent only to an https endpoint; over http the same request goes out without `Authorization`.
- The live server answers errors as `{ error: { message } }` (the docs say `{ detail }`; both are read) and wants 2 to 10 score levels.
- Engine pitfalls that shaped the code: no `claude-code` type import, no `any`, no `import()`, no `$.<noun>` passed as a bare value, one matcher-less hook per event, hooks are named function literals; `hooks/*.mjs` is built unmangled.
- Code was copied from jevfort (types, URL regex, request/timeout race), not imported: plugins ship standalone.
- Commands: `pnpm --filter jev-api build`, `pnpm --filter jev-api test`, `pnpm lint`, `claude plugin validate jev-api/plugin`.
- `tests/register.test.mts` has a live smoke block that runs only when `JEV_URL` is set in the shell (plus optional `TYPESAFE_API_KEY`, `TYPESAFE_DEFAULT_MODEL`); never put a URL in the repo.

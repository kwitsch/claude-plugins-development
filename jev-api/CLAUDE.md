# jev-api

Mods-only plugin: a function-hooks module that registers the System One question types `noul`, `choice`, `score` as tools (`mcp__jev-api__<type>`), plus `batch` (`state` and a `questions` array of `{ type, instructions, criteria }`, one request, answers as a JSON array in question order, all or nothing), and answers them. jevfort asks Jev only through `batch`: renaming it or changing its input or answer shape breaks jevfort.

- `src/hooks/register.mts` holds everything: no imports, HTTP through `$.http.fetch`. Two matcher-less hooks: `session.start` always registers the four tools (`Promise.allSettled`; a failed one is logged via `$.ui.log`) and records the name the engine returned for each (only in the `mcp__<plugin>__<type>` form) next to the default `mcp__jev-api__<type>` names, `tool.call` answers those names and passes every other tool to `next(e)`. A registered tool that no hook answers fails, so never call `next(e)` for `noul`/`choice`/`score`/`batch`, and the hook catches its own throws (a refused `$.env.get`) to answer them too.
- Errors are `{ deny: "<tool>: <reason>" }` (`batch` input errors name the question: `questions[<i>]: ...`): core drops a hook's own `isError` (live on 2.1.322 the model got the error as a normal result), while a `deny` reaches it as an error result.
- Call-time gate: on every call, before input validation, at least one of `TYPESAFE_API_KEY`, `TYPESAFE_BASE_URL`, `JEV_URL` must be non-blank, else a local error without a request. Endpoint: `JEV_URL` > `${TYPESAFE_BASE_URL}/v1/systemone` > `https://api.typesafe.ai/v1/systemone`; an invalid set value is an error, never a fallback. Model `TYPESAFE_DEFAULT_MODEL` or `jev-latest`; timeout via `$.clock.after`, cancelled when the request settles: the call's optional `timeout` input in seconds, else the `userConfig` option `timeout` (`register(on, options)`), else 20 s; a value counts only as a finite number > 0, anything else falls through silently (the engine caps one `$.http.fetch` at 30 s itself, so its `aborted: no complete answer` error comes first above 30); an aborted `next.signal` answers at once. The engine's fetch errors quote the URL, so `ask()` puts the variable's name in its place. The bearer key is sent only to an https endpoint; over http the same request goes out without `Authorization`.
- The live server answers errors as `{ error: { message } }` (the docs say `{ detail }`; both are read) and wants 2 to 10 score levels.
- Engine pitfalls that shaped the code: no `claude-code` type import, no `any`, no `import()`, no `$.<noun>` passed as a bare value, one matcher-less hook per event, hooks are named function literals; `hooks/*.mjs` is built unmangled.
- Code was copied from jevfort (types, URL regex, request/timeout race), not imported: plugins ship standalone.
- Commands: `pnpm --filter jev-api build`, `pnpm --filter jev-api test`, `pnpm lint`, `claude plugin validate jev-api/plugin`.
- `tests/register.test.mts` has a live smoke block that runs only when `JEV_URL` is set in the shell (plus optional `TYPESAFE_API_KEY`, `TYPESAFE_DEFAULT_MODEL`); never put a URL in the repo.

# Workflow scripts: why they are built this way

The reasons behind the constraints in the rule [workflows.md](../../../../../taskflow/.claude/rules/workflows.md) and the workflow parts of [CLAUDE.md](../../../../../taskflow/CLAUDE.md). Carried over unchanged from kwitsch/claude-plugins (`plugins/taskflow/CLAUDE.md` and `plugins/taskflow/workflows/CLAUDE.md` at `1404384`) when taskflow moved here on 2026-11-24.

- Run by name, never `scriptPath`: the skill calls `Workflow({name: "taskflow:build-task-<name>", args})`. The Workflow tool rejects a `scriptPath` it cannot itself read, and the plugin cache is outside the session's working directories; taskflow 2.0.0 shipped `scriptPath` calls and every run failed (live, the 2.0.0 regression).
- Not modules: Workflow-tool scripts run inside an implicit async wrapper with an injected `args` global, so top-level `await`/`return` are valid there but a standalone ES-module parser rejects them. Hence the root `.oxlintrc.json` ignore `**/*.workflow.js`, and the scripts are not ported to TypeScript (the preset has no workflow output type, and a port would change the shipped scripts).
- Shipped as assets: this repository's layout allowlist (`development/scripts/check-plugin-layout.ts`) rejects `workflows/*.workflow.js` and `skills/<skill>/workflows/*.md` (build-task's four refs, spec-task's `spec.md`, plan-task's `plan.md`), so the 12 files are listed by exact path in `pluginBuild.assets` (user decision 2026-11-24, precedent cc-knowledge's `install.sh`). Rejected: renaming the usage docs to `*.reference.md` (changes shipped names and the `SKILL.md` links), widening the allowlist (a repo-wide rule change).
- Unpinned model aliases: pinned model IDs caused problems in practice and were removed across the board; every role floats on its family alias. The tests sweep the plugin for a pinned ID.
- The `agent()` `model` option overrides the agent frontmatter `model` (confirmed in taskflow sessions before the move), so the size-driven designer and planner models work although both are plugin agents.
- No narration: agents run headless inside a Workflow, so prose between tool calls is wasted tokens; only the final message (report or schema-forced output) is consumed. The built-in `agentType: "Explore"` path carries the rule only in its per-call prompt because its system prompt is foreign to the plugin.
- English pipeline files: only other pipeline agents read the explore, draft, spec, plan, implement and review files, so one working language beats mirroring the request. `pr-author` is left out because the PR/MR title and body are human-facing and follow the repo's documentation language.
- Designer `keypoints`/`openQuestions`: a model that conflates the two fields fails `StructuredOutput` schema validation repeatedly, or worse, emits schema-valid placeholder junk that sails into the pipeline undetected; hence the explicit prompt sentence and the retry on contamination markers (`<openQuestions`, `</invoke`).
- Ponytail reuse ladder: ponytail is an external, non-allowlisted-marketplace plugin, so its reuse ladder is embedded as static prose in `designer.md` and `design-reviewer.md` instead of a runtime `Skill`/`dependencies` reference; drift from upstream is the accepted trade-off. The review step is the `review-task` skill: [review-task.md](review-task.md).
- Result files: the scribes and ship's pr-author write with the Write tool because the pipeline files live in the session scratchpad, which is outside the checkout and skipped by the formatter hooks ([scope-and-base.md](../../universal-format/design/scope-and-base.md)), so nothing rewrites them (docs). The former Bash heredoc was refused by the worktree-isolation guard whenever a body line started with `{`, `[` or `}` ([worktree-and-auto-mode-sessions.md](../../../pitfalls/worktree-and-auto-mode-sessions.md)), and the retry repeated the identical command, which fails the same way. Write is not subject to that check, so the one retry is the same Write call; a Bash-based write path (heredoc or printf) was rejected by the user on 2026-11-25. The JSON result files accept only the exact UTF-8 byte count or one more (a trailing newline the model may add) so a truncated JSON file never passes; the explore markdown is checked by structure instead: the script wraps each Explore job's report in a `## Lens: <name>` header and an `_End of lens: <name>_` footer, and the `explore-scribe` agent Reads the written file back and reports the pairs it found; failed explorers and an empty memory recall get no block (a placeholder body would read as a finding), and the retry only re-reads a file that was written. The former size floor (a fixed share of the expected byte count) let same-size or slightly short alterations through and needed Bash for `wc -c`; a trailing footer per lens catches truncation and needs only Read. Restricting the scribe to Read and Write needs an agent file with a frontmatter `tools` allowlist, because the Workflow `agent()` call has no tools option (its options are `label`, `phase`, `schema`, `model`, `effort`, `isolation`, `agentType`).
- Spec after the intent confirmation: the intent question shows only the design return's `keypoints`, and the spec script takes only `DRAFT_PATH`/`SPEC_PATH` and adds nothing new, so running it before the "Yes" wasted a spec run on every correction round and let a spec failure block an approval that does not depend on it. build-task therefore runs the spec once, as step 4, after the "Yes" (taskflow 2.3.0). Since taskflow 3.2.0 build-task's step 4 calls the `spec-task` skill once, and that skill runs the spec script ([spec-and-plan-skills.md](spec-and-plan-skills.md)).
- graphmind: availability is detected once per skill (`build-task/SKILL.md`; `plan-task/SKILL.md` for the plan script) and passed in through `args` ("inject before query", kwitsch/claude-plugins `.claude/rules/script-authoring.md` section 4), so the scripts never self-probe or re-query per subsystem. The scout stays on `agentType: "Explore"` because it is a coarse survey (1-4 subsystem names), not code-location finding. Project memory is searched once after the explorers, not per explorer.

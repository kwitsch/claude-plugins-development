# Settle window and owner routing (F34 0.16.0, rebuilt by F40 0.17.0)

User requests: 2026-11-14 (F34) "a finding that a following edit already repaired must not wake Claude"; 2026-11-15 (F40) after a transcript mining of 133 wake-ups (`development/wiki/plugins/universal-lint/tasks/F40-mid-edit-findings.md`): route findings to the agent that made the edit, report the final state of an edit burst once, sweep at turn end. F40 narrows "no debounce" (2026-11-06: the lint still starts at once, only the report waits) and replaces F23's "no superseded-lint drop" by a hand-off to the newest lint; F34's line-local rule (drop a finding only when a later edit rewrote its line), F35 (no hold for foreign or unlocated findings) and F36 (`gateFinding` mode `"drop"`) are gone.

- **Owner** (`ownerOf`) = first 16 hex of `hashPath(session_id + "\0" + agent_id)`; `agent_id` is present only inside a subagent (Agent tool and workflow agents, `agent_type: "workflow-subagent"`; live 2.1.325). Findings go to the owner of the edit only. FileChanged payloads name no agent: the main conversation owns them.
- **Journal** `${CLAUDE_PLUGIN_DATA || os.tmpdir()}/settle/<hashPath(real)>-<15-digit ms>-<pid>-<owner>.json` = `PendingRecord` `{hunks, ranges, digest, before, fp, cwd}`: one per Write/Edit (`lintFileHandler`, after the scope and empty-patch checks) and one per FileChanged whose digest check says the content changed outside Write/Edit (`hunks: null`); the digest-matched echo records nothing. `digest` = sha256 base64 of the content the tool wrote (`writtenContent`, never the disk: a change landing between the tool and its hook must not be folded into the record; the disk for FileChanged), `before` = digest of an Edit's `originalFile`. A record means "an edit no report has covered yet" and stays until a report claims it, a lint finds the file clean (`settleClean`: content and journal tail unchanged during the lint) or it is older than `PENDING_TTL_MS` (24 h; names dated more than 90 s ahead are pruned too, a stepped-back clock would sort them last). `recordEdit` also writes the owner's activity stamp `settle/act/<owner>` (epoch ms).
- **Subagent edits are not linted at PostToolUse** (journal and `written/` digest only): exit 2 of an `asyncRewake` hook wakes the main conversation, never the subagent (82 of 133 mined wake-ups). `SubagentStop` reports to the agent itself. Without a journal record (unwritable data dir) the lint runs and reports as before (fail open).
- **Gate = lines of every pending edit** (`pendingRanges`, used by `lintFileHandler` through `pendingUnion` and by the sweep): each record's `ranges` carried through the hunks of the records after it (`carryLine`), so a lint also reports what an earlier, superseded edit left broken (F23's Edit A / Edit B case). The records must chain (`before` = digest of the record before, last digest = the content linted); a broken chain (unjournaled change, formatter rewrite, hooks journaling out of edit order, CRLF file), a record without hunks (Write, FileChanged) or an unreadable journal mean the whole file (report more, never less). One record alone uses its own `ranges` without a digest check, as before the journal existed. `hasForeignLineBreak` files stay whole-file.
- **Hold** (`settleFindings`, PostToolUse and FileChanged, outside slot and locks): findings of any kind wait until the owner has journaled no Write/Edit, on any file, for `SETTLE_MS` (20 s; `settleWaitMs(uptime, idle)` caps the wait 1 s before the 90 s backstop, then the rules below apply at once), polling journal and stamp every `SETTLE_POLL_MS` (250 ms). Reported only when all hold: the file was unchanged during the lint (`d0 === d1`, journal tail unchanged: an edit and its exact undo counts as a change), no newer record of file and owner exists (that lint owns the report), the file still has digest `d0` after the hold, and removing the own record succeeds (the claim; the older records of file and owner are then cleared). Every other case reports nothing and leaves the records for the next lint or the sweep. No own record, an unreadable file or journal: reported at once (fail open).
- **Sweep** (`sweepHandler`, `Stop` and `SubagentStop`, synchronous hooks, exit 2 keeps the stopping agent going; live 2.1.325): per file with records of the owner: claim (remove the newest record, then the rest), scope again with the record's `cwd` and `fp`, gate with `pendingRanges`, lint; at most `FILE_CHANGED_SLOTS` files at a time, a file past `slotDeadlineMs(ext)` of process uptime is left pending. Findings set `settle/act/<owner>.blocked`; a stop with `stop_hook_active: true` and that marker is let through without a sweep (never block one stop twice), a fresh stop removes the marker. `pruneActivity` drops stamps and markers older than 24 h.
- **Headless** (`claude -p`, `CLAUDE_CODE_ENTRYPOINT` starts with `sdk`; interactive is `cli`): the hook is not backgrounded there, no later edit can arrive, so nothing is held (0.16.x delayed each finding by 5 s). Subagent routing and the sweeps work the same.
- **Seam** `UNIVERSAL_LINT_SETTLE_MS` (finite number >= 0) replaces the quiet time, also in headless runs; tests and `scripts/perf.ts` use it. Not a user setting (CLAUDE.md "No userConfig").
- **Residuals.** (1) A subagent's second stop after a report is not swept (its fix edits stay unreported; a subagent killed without `SubagentStop` leaves its records to the TTL). (2) A file not swept in time at a subagent's stop is never reported. (3) A watched file that a subagent changes outside Write/Edit, or that a formatter rewrites after a subagent's edit, is linted by FileChanged and reported to the main conversation (FileChanged has no agent; 15 FileChanged wake-ups in all transcripts). (4) The sweep trusts `fp` and `cwd` of a record: in the `os.tmpdir()` fallback another local user who knows the session id could plant one (same class as `written/`). (5) A broken chain reports whole-file findings, also old ones (a formatter that rewrites after an edit, CRLF files with more than one pending edit). (6) Line numbers in a finding reported after the hold are those of the content linted; the report only happens while the file still has that content. (7) A held lint parks one node process (no child) for up to the quiet time; a lint that will report nothing because the file changed still waits out its hold. (8) Journal order is the hooks' write order: an out-of-order pair breaks the chain (whole file) and the earlier-named record's lint stays silent, the other reports. (9) Stop is synchronous: a turn that ends with pending files waits for their lint.

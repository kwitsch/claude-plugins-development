# Settle window and owner routing (F34 0.16.0, rebuilt by F40 0.17.0)

User requests: 2026-11-14 (F34) "a finding that a following edit already repaired must not wake Claude"; 2026-11-15 (F40) after a transcript mining of 133 wake-ups (`development/wiki/plugins/universal-lint/tasks/F40-mid-edit-findings.md`): route findings to the agent that made the edit, report the final state of an edit burst once, sweep at turn end. F40 narrows "no debounce" (2026-11-06: the lint still starts at once, only the report waits) and replaces F23's "no superseded-lint drop" by a hand-off to the newest lint; F34's line-local rule (drop a finding only when a later edit rewrote its line), F35 (no hold for foreign or unlocated findings) and F36 (`gateFinding` mode `"drop"`) are gone.

- **Owner** (`ownerOf`) = first 16 hex of `hashPath(session_id + "\0" + agent_id)`; `agent_id` is present only inside a subagent (Agent tool and workflow agents, `agent_type: "workflow-subagent"`; live 2.1.325). Findings go to the owner of the edit only. FileChanged payloads name no agent: the main conversation owns them.
- **Journal** (in memory since 0.18.0: the server's Map of records, named `<hashPath(real)>-<12-digit seq>-<15-digit ms>-<owner>.json` and ordered by the sequence number, so a wall clock that steps back cannot make a later edit sort before an earlier one (it did when the milliseconds came first, a delayed report until the Stop sweep, measured 2026-11-27); earlier state: files `${CLAUDE_PLUGIN_DATA || os.tmpdir()}/settle/<hashPath(real)>-<15-digit ms>-<pid>-<owner>.json`) = `PendingRecord` `{hunks, ranges, digest, before, fp, cwd}`: one per Write/Edit (`lintFileHandler`, after the scope and empty-patch checks) and one per FileChanged whose digest check says the content changed outside Write/Edit (`hunks: null`); the digest-matched echo records nothing. `digest` = sha256 base64 of the content the tool wrote (`writtenContent`, never the disk: a change landing between the tool and its hook must not be folded into the record; the disk for FileChanged), `before` = digest of an Edit's `originalFile`. A record means "an edit no report has covered yet" and stays until a report claims it, a lint finds the file clean (`settleClean`: content and journal tail unchanged during the lint) or it is older than `PENDING_TTL_MS` (24 h; the age is pruned at most once per `JOURNAL_PRUNE_MS`, 1 s, because a prune walks the whole journal and a FileChanged burst journals one record per event). `recordEdit` also writes the owner's activity stamp (epoch ms, in memory). A claim is a map delete, not a file removal.
- **Subagent edits are not linted at PostToolUse** (journal and the in-memory `written` digest only): a finding would reach the main conversation, never the subagent (0.17.x: exit 2 of an `asyncRewake` hook wakes the main conversation, 82 of 133 mined wake-ups). `SubagentStop` reports to the agent itself. Without a journal record (an unreadable file for the digest) the lint runs and reports as before (fail open).
- **Gate = lines of every pending edit** (`pendingRanges`, used by `lintFileHandler` through `pendingUnion` and by the sweep): each record's `ranges` carried through the hunks of the records after it (`carryLine`), so a lint also reports what an earlier, superseded edit left broken (F23's Edit A / Edit B case). The records must chain (`before` = digest of the record before, last digest = the content linted); a broken chain (unjournaled change, formatter rewrite, hooks journaling out of edit order, CRLF file), a record without hunks (Write, FileChanged) or an unreadable journal mean the whole file (report more, never less). One record alone uses its own `ranges` without a digest check, as before the journal existed. `hasForeignLineBreak` files stay whole-file.
- **Hold** (`settleFindings`, PostToolUse and FileChanged, outside slot and locks): findings of any kind wait until the owner has journaled no Write/Edit, on any file, for `SETTLE_MS` (20 s; `settleWaitMs(callTime, idle)` caps the wait 1 s before the call's 90 s deadline, then the rules below apply at once), polling journal and stamp every `SETTLE_POLL_MS` (250 ms). Reported only when all hold: the file was unchanged during the lint (`d0 === d1`, journal tail unchanged: an edit and its exact undo counts as a change), no newer record of file and owner exists (that lint owns the report), the file still has digest `d0` after the hold, and removing the own record succeeds (the claim, a map delete; the older records of file and owner are then cleared). Every other case reports nothing and leaves the records for the next lint or the sweep. No own record, an unreadable file or journal: reported at once (fail open).
- **Sweep** (`sweepHandler`, `Stop` and `SubagentStop`, synchronous hooks, exit 2 keeps the stopping agent going; live 2.1.325): per file with records of the owner: claim (remove the newest record, then the rest), scope again with the record's `cwd` and `fp`, gate with `pendingRanges`, lint; at most `FILE_CHANGED_SLOTS` files at a time, a file past `slotDeadlineMs(ext)` of call time is left pending. Findings set the owner's `blocked` marker (in memory, per owner); a stop with `stop_hook_active: true` and that marker is let through without a sweep (never block one stop twice), a fresh stop removes the marker. `pruneActivity` drops stamps and markers older than 24 h. The Stop and SubagentStop hooks are `mcp_tool` calls of the server (`stop`, timeout 100), so the sweep runs inside the server's per-call budget (`HOOK_TIMEOUT_MS`).
- **Headless** (`claude -p`, `CLAUDE_CODE_ENTRYPOINT` starts with `sdk`; interactive is `cli`): the hook is not backgrounded there, no later edit can arrive, so nothing is held (0.16.x delayed each finding by 5 s). Subagent routing and the sweeps work the same.
- **Seam** `UNIVERSAL_LINT_SETTLE_MS` (finite number >= 0) replaces the quiet time, also in headless runs; tests and `scripts/perf.ts` use it. Not a user setting (CLAUDE.md "No userConfig").

## Delivery matrix (0.18.0; one carrier per cell)

| Edit                         | `claude -p`                                 | interactive, turn running                                                                                                                                                                                                                               | interactive, idle                                                                                                                                                                           |
| ---------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| main conversation Write/Edit | `context` on that tool result (inline mode) | the turn ends inside the quiet time (the usual case for a turn's last edits): **Stop block** (the sweep claims the record before the hold ends). The hold ends while the turn runs: outbox, then `context` on the next main Write/Edit, else Stop block | a hold that ends after the turn's last stop was let through (for example the fix edit after a blocked stop): outbox, `next_report` `ready`, wake prompt, text as `prompt_submitted` context |
| subagent Write/Edit          | journal only; SubagentStop block (sweep)    | same                                                                                                                                                                                                                                                    | same                                                                                                                                                                                        |
| FileChanged                  | outbox (inline lint), Stop block            | outbox: `context` on the next main Write/Edit, else Stop block                                                                                                                                                                                          | outbox, `next_report` `ready`, wake prompt, text as `prompt_submitted` context                                                                                                              |

Finding text leaves the server only through the keyed `file_edited` answer (in-turn context), the hidden `stop` block and the hidden `prompt_submitted` context. `next_report` carries one word. A carrier takes whole reports from the outbox, oldest first, while they fit one message (`MAX_CONTEXT_CHARS`, 4000; the first always goes) and leaves the rest queued for the next carrier (`next_report` answers `ready` again while one is pending; a stop is blocked once per owner, so what a Stop block leaves behind waits for the next prompt or edit, and a headless run, which never wakes, ends with it undelivered): a report cut out of a joined text would be lost, because its journal records were claimed when it was released and nothing lints that file again (three FileChanged reports of 2.9 KB each came out as two, measured 2026-11-27; 0.17.x gave each report its own message). Idle starts when the mod sees the main conversation's `turn.complete` (no `agentId`) and arms `next_report`; it ends at the next UserPromptSubmit (`prompt_submitted` resolves the waiter `busy`; the hook runs for typed prompts and for the plugin's own wake prompt). `$.prompt.submit` is used only while idle.

Headless runs are inline (`settleWaitMs(0, 0) === 0`, no new setting): the server sees `sdk-cli` in `claude -p` (live 2.1.332, P3), so nothing is held and the wake is never armed.

- **Residuals.** (1) A subagent's second stop after a report is not swept (its fix edits stay unreported; a subagent killed without `SubagentStop` leaves its records to the TTL). (2) A file not swept in time at a subagent's stop is never reported. (3) A watched file that a subagent changes outside Write/Edit, or that a formatter rewrites after a subagent's edit, is linted by FileChanged and reported to the main conversation (FileChanged has no agent; 15 FileChanged wake-ups in all transcripts). (4) Records are server memory since 0.18.0: no other user can plant one; a keyed `file_edited` with an invented session id adds records for that id only (R4 (c) in [hook-design.md](hook-design.md)). (5) A broken chain reports whole-file findings, also old ones (a formatter that rewrites after an edit, CRLF files with more than one pending edit). (6) Line numbers in a finding reported after the hold are those of the content linted; the report only happens while the file still has that content. (7) A held lint waits one async timer in the server (no child process) for up to the quiet time; a lint that will report nothing because the file changed still waits out its hold. (8) Journal order is the hooks' write order: an out-of-order pair breaks the chain (whole file) and the earlier-named record's lint stays silent, the other reports. (9) Stop is synchronous: a turn that ends with pending files waits for their lint (the `stop` call, timeout 100). (10) R1: the records die with the server (a crash, a kill or `/reload-plugins` loses them; unreported findings of that moment are lost, fail open, and FileChanged lints one echo twice). (11) R3: a finding that becomes ready while a turn runs is delivered with the next Write/Edit or at the Stop block, not mid-turn (no verified mid-turn `$.prompt.submit`); a finding of the fix edit after a blocked stop waits for the idle wake in an interactive session; the mod's `prompt.submit` hook ends the wake loop at a typed prompt (`hook-design.md` "Cancellation and the idle window"), but a race of a few milliseconds remains (a waiter resolved `ready` just before a typed prompt's hook call: the user's prompt carries the findings as context and the wake prompt follows with nothing attached).

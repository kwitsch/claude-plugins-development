# graphmind-helper decisions

Why graphmind-helper is built the way it is: moved from the plugin's `CLAUDE.md` (memory files hold constraints only), plus where the binary lookup list lives.

- Rebuilt from three Node command hooks (0.1.0) to a mod (0.2.0): measured here, a CLI call costs about 9 ms and a Node cold start 28 ms, so the gain is the Node start per hook call (every prompt, every Grep/Glob/Agent/Bash call) and in-memory state instead of state files. The 186 ms code search is the search itself (measured 2026-11-14).
- Approach B (decided headless): MCP tools for status, map, recent memory and code search; `$.process.run` (no shell) only for what the tools cannot do: `memory list --priority` (the MCP list has no priority filter or star, ids are UUIDs) and `memory search --no-recall` (no such tool option; graphmind issue #112) (measured 2026-11-14).
- `binaryDirs` lives once in `development/shared/src/graphmind-paths.ts` (`@shared/graphmind-paths.js`) and is inlined by the tsdown build into `plugin/hooks/register.js` (through `terms.ts`) and into `plugin/mcp/mcp.mjs` (through `src/bin/common.ts`; `plugin/bin/mcp.mjs` before 0.2.5) (build 2026-11-20, 0.2.3). The ban on `@shared` in the entry no longer applies ([tsdown-plugin-build](../../../decisions/tsdown-plugin-build.md)); the wrapper `binaryPaths` in `terms.ts` dates from that ban and stays (removing it is an unrelated refactor). Rejected earlier: a plugin-local `src/shared/graphmind-paths.ts` imported relatively (jev-api's pattern); a copy in `src/bin/common.ts` (five duplicated lines kept in step by tests on both sides); `bin/common.ts` importing the hooks bundle. The form before the tsdown build (0.2.2: helper bundled into `lib.mjs`, shared module shipped to `plugin/shared/`): [shared-source-layer](../../../decisions/shared-source-layer.md).

# graphmind-helper decisions

Why graphmind-helper is built the way it is: moved from the plugin's `CLAUDE.md` (memory files hold constraints only), plus where the binary lookup list lives.

- Rebuilt from three Node command hooks (0.1.0) to a mod (0.2.0): measured here, a CLI call costs about 9 ms and a Node cold start 28 ms, so the gain is the Node start per hook call (every prompt, every Grep/Glob/Agent/Bash call) and in-memory state instead of state files. The 186 ms code search is the search itself (measured 2026-11-14).
- Approach B (decided headless): MCP tools for status, map, recent memory and code search; `$.process.run` (no shell) only for what the tools cannot do: `memory list --priority` (the MCP list has no priority filter or star, ids are UUIDs) and `memory search --no-recall` (no such tool option; graphmind issue #112) (measured 2026-11-14).
- `binaryDirs` lives once in `development/shared/src/graphmind-paths.ts` (`@shared/graphmind-paths.js`), imported by the bundled helper `terms.ts` (which wraps it as `binaryPaths` for the entry, since helpers export declarations only and the entry may not import `@shared`) and by `src/bin/common.ts` (build 2026-11-20; not checked live). Rejected: a plugin-local `src/shared/graphmind-paths.ts` imported relatively (jev-api's pattern; needs no build change, but the user asked for the `@shared` layer and the guard relaxation); a copy in `src/bin/common.ts` (five duplicated lines kept in step by tests on both sides); `bin/common.ts` importing `../hooks/lib.js` (no such source, the type check fails, and the wrapper would load the whole hooks bundle). This needed the build to accept `@shared` imports from bundled helpers: [shared-source-layer](../../../decisions/shared-source-layer.md).

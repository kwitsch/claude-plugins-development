# development/

Shared developer tooling, no plugin. Not versioned or released, except `shared/` (a package on GitHub Packages, below).

- `scripts/`: `check-plugin-layout.ts` (what `plugin/` may hold, run by CI after each plugin build); `tests/ships.test.ts` (every state of `.github/scripts/ships.sh` and the helpers `changed-plugins.sh`, `ships-notice.sh`; `pnpm --filter build-scripts test`); `plugin-test.ts` (runs a mod's `claude-tests/` under `claude plugin test`); `wiki-check.ts` (consistency check of the wiki, part of `pnpm lint` and of the PR workflow).
- `shared/src/`: code several plugins use, imported as `@shared/<name>.js`, inlined by the build ([tsdown-build.md](../.claude/rules/tsdown-build.md)), nothing ships as `plugin/shared/`. `development/shared` is also the package `@kwitsch/claude-code-plugin-shared`, published by `.github/workflows/publish-shared.yml` ([ci.md](../.claude/rules/ci.md)); plugins still use the alias until they pin it. A change there changes each `@shared` consumer's build: CI demands each consumer's version bump. Reasons and plan: [shared-source-layer](wiki/decisions/shared-source-layer.md).
- `wiki/`: the repository's knowledge base for agent sessions (index, log, topic pages); its own `CLAUDE.md` says what goes there and how.
- `vitest/claude-engine/`: the workspace package `claude-engine-vitest` (no `plugin/`), the shared vitest stand-in for Claude Code's mod test kit (`claude-code/testing`), a `workspace:*` devDependency of plugins with function-hooks modules; it loads a mod by file URL (unit tests: `src/hooks/register.ts`). It also holds `claude-code-testing.d.ts`, the types of the official kit for `claude-tests/`.
